# Prompt 00 — Strict Project Start

Работай в режиме `/strict-plan-execution`.

## Правила

1. Не начинай писать production-код.
2. Прочитай `CLAUDE.md`, `docs/`, `data/`, `references/README.md`.
3. Вызови subagent `planner`.
4. Planner должен подготовить подробный `WORKPLAN.md`.
5. После planner обязательно вызови `skeptic` для критики плана.
6. Исправляй план и повторно вызывай skeptic до `VERDICT: PASS`.
7. Покажи мне финальный план целиком.
8. Отдельно покажи:
   - assumptions;
   - риски;
   - решения, которые должен принять я;
   - что не входит в scope.
9. Не переходи к реализации, пока я явно не напишу, что план утверждён.

После утверждения:

1. Выполняй строго один шаг.
2. Запускай указанные для шага проверки.
3. Записывай результат в `WORKLOG.md`.
4. После каждого шага обязательно вызывай `skeptic`.
5. При `FAIL` исправляй шаг и повторяй review.
6. При `BLOCKED` остановись.
7. Не начинай следующий шаг без `PASS`.
8. После каждого milestone вызывай профильных reviewers.
9. После каждого завершённого шага присылай:
   - что сделано;
   - какие файлы изменены;
   - какие команды запущены;
   - их результат;
   - verdict skeptic;
   - что будет следующим шагом.

Никакие слова основной сессии «всё сделано правильно» не заменяют независимый verdict skeptic.
