### 2026-07-14 — Порт разработки/e2e зафиксирован на 3100, host — localhost (Plan Amendment 1)

- Контекст: при первом прогоне `npm run test:e2e` тест прошёл, но проверил совершенно другой,
  посторонний сайт ("Qbit-Studio-AI"), потому что порт 3000 на машине разработки уже занят чужим
  Next.js-процессом, а `playwright.config.ts` (`reuseExistingServer: !CI`) молча переиспользовал
  уже слушающий сервер вместо запуска своего. Skeptic (review исполнения шага) вернул FAIL и
  потребовал: (1) явную amendment-запись вместо тихой правки уже одобренного раздела Step 1
  (нарушение non-negotiable правила CLAUDE.md); (2) устранить обнаруженную при этом реальную
  консольную ошибку в dev-режиме при host `127.0.0.1` (Next.js 16 `allowedDevOrigins` блокирует
  HMR-websocket для числового IP), которой нет при host `localhost`.
- Варианты порта: (a) оставить порт 3000 по умолчанию (рискует повторно зацепить чужой процесс);
  (b) зафиксировать другой порт (3100); (c) preflight-проверка занятости порта перед стартом или
  динамически выделяемый свободный порт.
  Варианты host: (a) `127.0.0.1` (провоцирует HMR cross-origin ошибку в dev); (b) `localhost`
  (чисто в dev и prod, подтверждено headless-проверкой консоли браузера).
- Решение: порт 3100 (вариант b); host `localhost` везде — `package.json` (`next dev -p 3100`,
  `next start -p 3100`), `playwright.config.ts` (`baseURL`/`webServer.url` —
  `http://localhost:3100`), `README.md`, `WORKPLAN.md` (manual checks). Вариант (c) для порта не
  реализован сейчас — оставлен как нерешённый остаточный риск без владельца-шага (см. WORKPLAN.md
  Step 1, Risks), чтобы не расширять scope Step 1.
- Последствия: `npm run dev`/`npm run start`/`npm run test:e2e` этого проекта используют
  `localhost:3100`, а не порт Next.js по умолчанию. Если порт 3100 в будущем тоже окажется занят
  посторонним процессом, `reuseExistingServer` может повторить тот же класс ошибки — потребуется
  либо preflight-проверка, либо переход на динамический порт в отдельном будущем шаге.
- Skeptic review: 1-й review — FAIL (среди прочего: нет amendment-записи). После добавления
  amendment с самостоятельно проставленным `Status: APPROVED` — 2-й review вернул **BLOCKED**:
  исполнитель не вправе сам себя одобрять за пользователя, даже для технической правки внутри
  уже одобренного scope. Статус исправлен на `AWAITING_USER_APPROVAL`, вопрос задан пользователю.
- Согласование пользователя: **получено** 2026-07-14 ("Да, утверждаю порт 3100 / localhost").
  Остаточный риск (порт 3100 тоже может быть занят в будущем) пользователь решил оставить known
  issue без owner-шага — не назначать отдельным шагом плана, решать по факту при повторении.

### 2026-07-15 — Step 5: механизм URL-синхронизации при выборе/переключении/закрытии отдела (OQ-B)

- Контекст: клиентский выбор/переключение/закрытие отдела должно обновлять `?department=<id>` в
  адресной строке без полной перезагрузки страницы. Два кандидата с разными компромиссами
  (идиоматичность Next.js vs риск повторного рендера серверного дерева).
- Варианты: (a) Next.js `useRouter`/`useSearchParams` (`next/navigation`) — идиоматично для App
  Router, потенциально поддерживает браузерные назад/вперёд, но может инициировать повторный
  рендер серверного `page.tsx`/`HomepageShell` при каждой смене отдела; (b) сырой
  `history.pushState`/`replaceState` — чисто косметическое обновление URL, без серверного/
  React-рендер-цикла, не поддерживает браузерные назад/вперёд (вне scope шага в любом случае).
- Решение: (b) — `history.pushState`/`replaceState`.
- Последствия: URL-синхронизация в Step 5 — первый сырой DOM/browser API вызов в проекте в обход
  навигации Next.js; исключается риск повторного вызова adapter'ов `src/content/*` или заметного
  мигания при каждом переключении отдела (прямое смягчение риска, названного в Step 4: новый класс
  гидратационных проблем). Поддержка браузерных назад/вперёд остаётся вне scope Step 5, как и было
  зафиксировано в Out of scope независимо от этого решения.
- Согласование пользователя: получено 2026-07-15 напрямую через `AskUserQuestion` — выбран вариант
  "history.pushState/replaceState (рекомендую)".
