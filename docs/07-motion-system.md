# Motion System

## Принцип

Анимация объясняет источник, направление, задержку, изменение и точку решения человека.

## Уровни

1. **Ambient** — слабый свет, мониторы, небольшая активность.
2. **Interaction** — hover, focus, touch, selection.
3. **Explanation** — лид, обращение, кандидат, документ, статус.
4. **Transition** — overview ↔ department и department switch.

## Ориентиры времени

- hover/focus: 120–220 мс;
- label: 180–280 мс;
- selection: 180–320 мс;
- overview → department: 650–1000 мс;
- department switch: 450–800 мс;
- close: 550–900 мс.

## Уровень Transition — реализация (правка по факту, Step 16)

Переход между сценами реализован как **контролируемое приближение + crossfade**, без свободного
полёта камеры (`docs/03` «Камера») и **без pointer-параллакса** (OQ-A2-6, решение 2026-07-18 —
см. раздел ниже, он описывает не реализованное, а отложенное).

- Приходящая сцена проявляется анимацией `scale(1.04) → scale(1)` + `opacity 0 → 1` за 700 мс, то
  есть внутри вилки «overview → department: 650–1000 мс». Анимируются только `transform` и `opacity`
  (`docs/10`), поэтому переход не вызывает перекомпоновки и не трогает раскладку контента поверх.
- **Уходящая сцена не гасится по таймеру.** Она снимается только после того, как приходящая
  сообщила о готовности (успешная загрузка ЛИБО провал). Причина измерена, а не предположена: слои
  сцены монтируются с `key` по сцене (это защищает от «залипания» признака неудачной загрузки), и
  без удержания переход на медленном канале шёл через пустой кадр — 16 из 30 выборок без видимой
  сцены. С удержанием — 0 из 30.
- Ключ слоя привязан к САМОЙ СЦЕНЕ, а не к роли («уходящий»/«приходящий»). При ключе по роли
  уходящий слой оказывается новым DOM-элементом и стартует пустым — удерживать ему нечего.
- `prefers-reduced-motion: reduce` — приближение заменяется коротким fade. Отдельная ветка нужна
  именно потому, что глобальное правило схлопывает ДЛИТЕЛЬНОСТЬ, но не убирает `transform`: без неё
  пользователь получил бы не отсутствие движения, а его рывок.
- Критический контент (заголовок, боли, CTA, «Закрыть») от анимации не зависит: он в DOM и в дереве
  доступности с первого кадра и кликабелен во время перехода (`CLAUDE.md` Motion rules).

**Совокупный бюджет со Step 15.5.** Каскад появления блоков (0/1/2/3 с) проигрывается заново на
каждом переключении отдела поверх этого перехода, поэтому CTA становится ВИДИМЫМ примерно через
3.4 с. Это принятое поведение (прямой запрос пользователя), и оно допустимо ровно потому, что всё
это время CTA остаётся ДОСТУПНЫМ — иначе motion удерживал бы коммерческий путь.

## Pointer parallax

- ограниченный диапазон;
- rAF;
- без React state на каждом pointermove;
- отключение на touch, слабых устройствах и reduced motion;
- не влияет на координаты controls.

## До/после

Использовать один процесс, который меняется, или пошаговую последовательность. Не перегружать split-screen.

## Reduced motion

- убрать параллакс;
- заменить камерный перелёт коротким fade;
- остановить бесконечные циклы;
- сохранить статусы и причинно-следственную связь;
- оставить все функции.

## Пауза

Останавливать необязательные анимации при скрытой вкладке, модальном окне, неактивной сцене и ошибке производительности.

## Запреты

- обязательная интро-заставка;
- скролл-джекинг;
- критические кнопки после длинной анимации;
- вспышки;
- автоматический звук;
- постоянное движение всей сцены.
