## 1. Архитектура

Next.js 16.2.10, App Router, React 19.2.4, TypeScript, SQLite через встроенный `node:sqlite`.
Единственная production-зависимость сверх фреймворка — `zod`. Нативных сборок нет.

### Карта маршрутов

| Тип | Маршруты | Рендер |
| --- | --- | --- |
| Публичные страницы | `/`, `/contacts`, `/documents`, `/faq`, `/how-we-work` | Static |
| Публичные разделы | `/blog/[[...slug]]`, `/products/[[...slug]]` | SSG + `dynamicParams` |
| Служебные | `/robots.txt`, `/sitemap.xml` | Static |
| Вход | `/login` | Dynamic |
| Админ-панель | `/admin`, `/admin/{blog,products,departments,documents,contacts}` | Dynamic (`force-dynamic`) |
| Публичное API | `/api/content/[section]`, `/api/files/[...path]`, `/api/contact`, `/api/task` | Dynamic |
| Админское API | `/api/admin/{login,logout,articles,articles/[id],products,products/[id],departments/[id],documents,documents/[id],contacts,pages/[key]}` | Dynamic |

### Точки входа пользовательских данных

| Точка входа | Аутентификация | Валидация | Ограничение частоты |
| --- | --- | --- | --- |
| `POST /api/admin/login` | — (вход) | `loginSchema` | адресный + глобальный (БД) |
| `POST /api/contact` | нет | `contactSubmissionSchema` | 5/мин на адрес, 40/мин общее |
| `POST /api/task` | нет | `taskRequestSchema` | 3/мин на адрес, 30/мин общее |
| `GET /api/content/[section]` | нет | закрытый список из 5 разделов | нет (только чтение опубликованного) |
| `GET /api/files/[...path]` | нет | нормализация пути + белый список расширений | нет |
| Все `POST/PUT/DELETE /api/admin/*` | `requireSession()` | Zod по каждому роуту | — |
| Загрузка файлов (`multipart`) | `requireSession()` | белые списки расширений и MIME, лимит 25 МБ | — |

### Разделение server/client

Нарушений не обнаружено. `src/server/**` не импортируется ни из одного `"use client"`-модуля;
`node:sqlite`, `node:fs`, `node:crypto` встречаются только в серверных модулях и route handlers.
Секреты читаются точечно в местах использования, а не на уровне модуля — отсутствующая переменная
роняет авторизацию, а не весь сайт.

## 7. Кэширование и актуализация контента

Публичные страницы пререндерятся; актуальность обеспечивается `revalidatePath` после каждой записи.

- `revalidateSection` вызывает и `revalidatePath(section)`, и
  `revalidatePath("<section>/[[...slug]]", "page")` — верный шаблон для optional catch-all.
- `dynamicParams = true` на обеих страницах: slug, созданный после сборки, резолвится без пересборки.
- Контакты и отделы поднимаются до `revalidateSiteWide()` (`"/"`, `"layout"`), потому что питают
  шапку.
- `/admin` — `force-dynamic`, не кэшируется; после правок добавлен `no-store`.

**Что проверено:** корректность вызовов по коду и то, что сборка проходит.
**Что НЕ проверено вживую:** полный матричный сценарий из задания — 5 отделов, 10 продуктов,
контакты, создание/редактирование/публикация/снятие/удаление статьи, загрузка/публикация/порядок/

### Первая редакция C-5 была неверной — поймано скептиком

Исправление применяло к ОДНОМУ отделу схему КОЛЛЕКЦИИ: `departmentsSchema` — это
`z.array(departmentSchema).length(5)` плюс требование «все пять идентификаторов без дублей в
фиксированном порядке». Массив из одного элемента её не проходит **никогда**.

Последствие было тяжелее исходной проблемы: каждый отдел уходил в ветку ошибки и подменялся
seed-текстом, то есть **правки отделов через админ-панель переставали появляться на сайте**, а на
каждый рендер главной уходило пять `console.error` и пять заведомо провальных разборов.

Дефект был невидим для всех имевшихся проверок: содержимое базы побайтово совпадает с
`data/departments.json`, E2E идёт против той же базы, а тесты покрывали только скрытие и порчу — ни
один не утверждал, что **отличный от seed** корректный контент доходит до читателя.

Исправлено на `departmentSchema` (схема одного отдела); коллекционные инварианты к выборке
опубликованных отделов неприменимы по существу — список штатно неполон, когда отдел скрыт.
Добавлены два регрессионных теста, и проверено, что они **падают** на прежней реализации.

**Ложные срабатывания, отклонённые review:** IDOR в новой раздаче файлов; поломка выдачи
предпросмотров; server-only код в клиентском бандле; `any`/`@ts-ignore`/отключения eslint (нет ни
одного); утечки слушателей и таймеров (у каждого есть cleanup, включая новый `transitionend`);
вложенные транзакции SQLite; открытый редирект через `?next=`.
