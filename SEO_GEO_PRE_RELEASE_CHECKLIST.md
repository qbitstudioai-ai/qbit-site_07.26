# Чек-лист SEO/GEO перед запуском на allqbit.ru и после него

**Дата составления:** 2026-07-28
Отчёт об аудите: [SEO_GEO_AUDIT.md](SEO_GEO_AUDIT.md).

Регистрация в Google Search Console и Яндекс Вебмастере **не выполнялась** — она требует доступа
владельца. Фиктивные коды подтверждения не проставлялись. Ниже — что нужно сделать и в каком
порядке.

Общий по проекту чек-лист развёртывания лежит в `PRE_RELEASE_CHECKLIST.md`; здесь только SEO и GEO.

---

## A. Обязательно до запуска

### A1. Домен и схема — уровень обратного прокси

Ни один из пунктов этого блока не реализуем в коде приложения.

- [ ] `http://allqbit.ru` → `https://allqbit.ru`, постоянной переадресацией 301.
- [ ] `http://www.allqbit.ru` и `https://www.allqbit.ru` → `https://allqbit.ru`, 301. Направление
      выбрано по canonical, уже проставленному в коде: основной адрес **без** `www`.
- [ ] Переадресация **в один шаг**: `http://www` → `https://` без промежуточной остановки.
      Цепочек редиректов быть не должно.
- [ ] Единая политика завершающего слэша: адреса без него. Приложение уже отдаёт такой вид, и
      canonical с sitemap ему соответствуют — нужно, чтобы прокси не добавлял слэш.
- [ ] Валидный TLS-сертификат на `allqbit.ru` и `www.allqbit.ru` (второй нужен, чтобы переадресация
      с `www` вообще выполнилась).
- [ ] Прокси передаёт `Host: allqbit.ru` и `X-Forwarded-For` (см. `.env.example`, `TRUST_PROXY`).

### A2. Переменные окружения

- [ ] `NEXT_PUBLIC_SITE_URL` **не задавать**, либо задать ровно `https://allqbit.ru`. Значение по
      умолчанию в коде уже правильное. Ошибка здесь испортит сразу canonical, sitemap, Open Graph и
      JSON-LD на всём сайте.
- [ ] После деплоя проверить, что в исходном HTML нет `localhost` и адреса стенда.

### A3. Проверка отдаваемых файлов на боевом домене

- [ ] `https://allqbit.ru/robots.txt` — HTTP 200, `Content-Type: text/plain`, содержит
      `Sitemap: https://allqbit.ru/sitemap.xml`, закрывает `/api/`, `/admin`, `/login`.
- [ ] `https://allqbit.ru/sitemap.xml` — HTTP 200, `Content-Type` с `xml`, 23 адреса (или больше,
      если добавлены материалы), все на `https://allqbit.ru`.
- [ ] `https://allqbit.ru/og/qbit-og-1200x630.png` — HTTP 200, изображение 1200×630 открывается.
- [ ] Выборочно `curl` по трём страницам: `<title>`, `description`, `canonical`, `og:*` совпадают с
      матрицей маршрутов и указывают на боевой домен.

### A4. Индексация служебных разделов

- [ ] `https://allqbit.ru/admin` без сессии — редирект на `/login`.
- [ ] `https://allqbit.ru/login` — `<meta name="robots" content="noindex, nofollow, noarchive">`.
- [ ] Прямой адрес файла документа (`/api/files/documents/<id>`) открывается для опубликованного
      документа и **не** открывается для снятого с публикации.

### A5. Проверки после сборки

- [ ] `npm run typecheck`, `npm run test`, `npm run build` — пройдены на боевой конфигурации.
- [ ] `npm run test:e2e` — пройдены. При единичном падении спецификаций слоя фотографий перезапустить:
      известная нестабильность при полной параллельности (см. отчёт, раздел 25).

## B. Сразу после размещения на allqbit.ru

- [ ] Открыть все 15 индексируемых адресов из матрицы маршрутов в чистом профиле браузера, без
      расширений. Проверить консоль и вкладку «Сеть»: ошибок сайта быть не должно. Ошибки расширений
      Chrome ошибками сайта не считать.
- [ ] Проверить `https://allqbit.ru` на мобильном устройстве.
- [ ] Проверить предпросмотр ссылки в Telegram и WhatsApp: должны показаться заголовок, описание и
      обложка. Это заодно подтверждает, что Open Graph доступен ботам, не выполняющим JavaScript.
- [ ] Проверить рекомендованный ранее переход CSP на `nonce` вместо `'unsafe-inline'` (вынесено в
      `PRE_RELEASE_CHECKLIST.md`) — на SEO не влияет, но относится к тем же заголовкам ответа.

## C. После подключения Google Search Console

- [ ] Подтвердить владение доменом. Способ — DNS-запись TXT (предпочтительно: подтверждает домен
      целиком) либо meta-тег.
- [ ] **Если выбран meta-тег:** место для него в коде готовится через поле `verification.google` в
      метаданных корневого layout. Сейчас оно **не заведено и оставлено пустым намеренно** —
      фиктивные коды подтверждения не проставляются. Добавить только реальное значение из консоли.
- [ ] Отправить `https://allqbit.ru/sitemap.xml`.
- [ ] URL Inspection по одному адресу каждого типа: главная, продукт, статья, документы, FAQ,
      контакты. Проверить: страница доступна, canonical совпадает с ожидаемым, индексация разрешена,
      отрисованный HTML содержит основной текст.
- [ ] Отчёт «Индексирование страниц»: убедиться, что `/admin`, `/login` и `/api/*` не попали в
      выдачу, а исключены как ожидалось.
- [ ] Отчёт «Расширенные результаты»: проверить `Organization`, `BreadcrumbList`, `FAQPage`,
      `Article`. Ошибок быть не должно; предупреждения о необязательных полях допустимы.
- [ ] Проверить страницы через Rich Results Test и Schema Markup Validator.

## D. После подключения Яндекс Вебмастера

- [ ] Подтвердить права на сайт. Место для meta-тега — поле `verification.yandex`, сейчас
      **не заведено и пустое**; добавить только реальный код.
- [ ] Отправить `https://allqbit.ru/sitemap.xml`.
- [ ] «Индексирование → Страницы в поиске»: проверить, что попали именно 23 адреса из карты сайта.
- [ ] «Инструменты → Проверка ответа сервера» по адресу каждого типа: код 200, отсутствие лишних
      редиректов.
- [ ] «Инструменты → Валидатор микроразметки»: проверить JSON-LD.
- [ ] Указать основное зеркало `allqbit.ru` (без `www`) — совпадает с canonical в коде.
- [ ] Проверить региональную привязку и заполнить карточку организации, если владелец сочтёт нужным.

## E. Наблюдение после публикации

- [ ] Через 1–2 недели: сравнить число страниц в индексе Google и Яндекса с 23. Расхождение
      разобрать по конкретным адресам.
- [ ] Проверить логи обращений поисковых роботов: доходят ли они до всех разделов, не упираются ли
      в 404 или 5xx.
- [ ] Проверить, что после публикации новой статьи в админ-панели она появляется в
      `https://allqbit.ru/sitemap.xml` **без пересборки** (механизм `revalidateSection` уже
      реализован и покрыт тестами; на боевой конфигурации подтвердить фактически).
- [ ] Проверить, что снятая с публикации статья исчезает из карты сайта и отдаёт 404.
- [ ] Проверить canonical на нескольких адресах с UTM-метками: должен оставаться без параметров.

## Чего делать не нужно

- Не добавлять `hreflang`: сайт только на русском.
- Не добавлять `meta keywords`.
- Не проставлять фиктивные коды подтверждения — оставлять поля пустыми до получения реальных.
- Не добавлять `llms.txt`, `ai.txt` и другие экспериментальные файлы без подтверждённой
  необходимости: ни одна поисковая или AI-система не заявляла их поддержку как условие
  индексирования.
- Не ставить `lastModified` всем строкам карты сайта текущей датой — это обесценивает сигнал.
- Не обещать себе и заказчику позиций, трафика или цитирования AI-системами: технических гарантий
  этого не существует.
